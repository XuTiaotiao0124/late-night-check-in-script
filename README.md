# 华天 wise 晚寝签到 · 青龙面板自动签到 + 企业微信推送

每天 21:01 自动完成「学生晚寝签到1」（签到时段 21:00–23:00），结果推送到企业微信群机器人。

**主用脚本：[wise_dorm_sign.js](wise_dorm_sign.js)**（青龙面板 / 任意 Node 服务器，零依赖）

> 另附 [wise_dorm_sign.sh](wise_dorm_sign.sh) 为 OpenWrt / busybox 版，备用（如果你以后想改成路由器跑）。
> 注意：`.sh` 版**只支持单账号**（`WQQD_ACCOUNT1` / `WQQD_PASSWORD1`，也兼容旧的 `WISE_ACCOUNT` / `WISE_PASSWORD`），多账号汇总推送只在 `.js` 版里有。

## 一、青龙「订阅」自动添加定时任务（推荐，之后脚本更新自动同步）

如果你想用 Gitee 仓库托管脚本，让青龙订阅拉取后**自动把签到任务建好**，按下面来（只做一次）。

### 1.1 脚本里已经写好了 cron

`wise_dorm_sign.js` 头部有一行注释：

```js
// cron: 1 21 * * *
```

这是给青龙看的**任务定时**。订阅开启「自动添加任务」后，青龙读到这行，就会自动建出 cron=`1 21 * * *`（21:01）的签到任务；**没有这行的话青龙会随机分时**，所以别删它。

### 1.2 在青龙面板创建订阅（粘贴 `ql repo` 命令自动填字段）

「订阅管理」→「新建订阅」，在弹窗的**名称**或**链接**输入框里，直接粘贴下面这段（改成你自己的仓库地址）：

```
ql repo https://gitee.com/xxxxxxxx/late-night-check-in-script.git wise_dorm_sign.js "" "" ""
```

青龙会自动解析并填好各字段（源自面板源码 `modal.tsx onPaste`）：

| ql 命令参数 | 填到的字段 | 说明 |
|---|---|---|
| `repo` | 类型 | 公开仓库（URL 以 http 开头） |
| 仓库 URL | 链接 | 你的 Gitee 仓库 `.git` 地址 |
| 第3个参数 | 白名单 | 写 `wise_dorm_sign.js`，只选中这一个脚本；多个关键词用 `\|` 分隔、支持正则 |
| 第4个参数 | 黑名单 | 留空 `""` |
| 第5个参数 | 依赖文件 | 留空 `""`（本脚本零依赖） |
| 第6个参数 | 分支 | 留空 `""`（默认主分支） |
| 第7个参数 | 文件后缀 | 默认 `js`，可不填 |

> 只想拉单个文件时用 `ql raw https://…/wise_dorm_sign.js`（类型自动判为「单文件」）。
> 白名单/黑名单/依赖都支持**多个关键词竖线 `|` 分隔、支持正则**。

### 1.3 创建后要确认的两个开关

- **「自动添加任务」**（autoAddCron）：默认`开`，保持开启 → 订阅跑一次后自动建出 `task wise_dorm_sign.js`（cron=`1 21 * * *`）。
- **「自动删除任务」**（autoDelCron）：默认`开`。它会在你删掉仓库里的脚本时把对应任务也删掉，避免残留。

### 1.4 手动补一条兜底任务

订阅只自动建 `1 21 * * *`（21:01）这一条；建议再**手动补一条 22:02 的兜底**，万一主任务失败，夜里还有一次机会：

| 任务 | 命令 | cron |
|---|---|---|
| 晚寝签到（主） | `task wise_dorm_sign.js` | `1 21 * * *` |
| 晚寝签到兜底 | `task wise_dorm_sign.js` | `2 22 * * *` |

### 1.5 注意：订阅的"定时"≠签到时间

「定时规则」（比如 `1 0 * * *` 或 interval）是青龙**多久去拉取一次仓库**，跟 21:01 签到无关，随便设成一天一次即可。设置完保存后再「运行一次」订阅，脚本会自动同步；以后你在 Gitee 改脚本，青龙按这个频率拉取自动更新任务。

> 更省事：手动搓「新建脚本 + 粘贴代码」也一样能用（见下节二），订阅只是让你更新脚本方便。

## 原理（为什么青龙异地服务器也能签）

签到页是 uni-app 前端，它只是把手机 GPS 经纬度当成**普通数字**塞进
`POST /api/flySource-yxgl/dormSignRecord/stuSign` 的 body 里。
服务端只用 haversine 计算「提交坐标 ↔ 宿舍登记坐标」的距离，再和任务允许半径（本任务 **400 米**）比较。

- 不校验 IP、不校验设备、不校验是否真的在定位。
- 所以青龙服务器在哪儿都无所谓，**把坐标写成宿舍附近即可，不需要模拟定位**。

默认提交坐标 `88.88888888888, 88.888888888888`（你平时签到的位置，距宿舍登记点约 23.7 米，远小于 400 米），并且每次会在 3 米内随机抖动，避免每天坐标完全一致。

## 二、青龙部署（5 步，真正要你动手的只有「改两行 + 填账号」）

### 1. 新建脚本

青龙面板 →「脚本管理」→ 新建 → 文件名 `wise_dorm_sign.js`，把 [wise_dorm_sign.js](wise_dorm_sign.js) 的内容整段粘贴进去保存。

**不需要 `npm install`**，脚本只用 Node 内置的 `https` / `crypto`。

### 2. 改脚本头部的配置区

打开脚本最上面，有一块 `const SETTINGS = { … }` 配置区，所有可调参数都在这一块里，每行右边只写「这是什么」：

```js
// ============================================================================
// 配置区（要改就改这里；设了同名环境变量会覆盖这里的值）
// ============================================================================
const SETTINGS = {
  SIGN_URL: '',                    // 签到链接
  LAT: 88.888888888888888,         // 纬度
  LNG: 88.888888888888888,         // 经度
  JITTER: 3,                       // 坐标抖动半径（米）
  DRY_RUN: false,                  // 演练模式
  FORCE: false,                    // 强制提交
  RETRY: 3,                        // 失败重试次数
  RETRY_WAIT: 30,                  // 重试间隔（秒）
  EARLY_WAIT: 120,                 // 早到等待（秒）
  QYWX_KEY: '',                    // 企业微信通知
  NOTIFY: true,                    // 推送开关
  NOTIFY_SKIP: false,              // 跳过也推送
  NOTIFY_ALREADY: false,           // 已签到也推送
};
```

**你实际要填的就两处**：

| 位置 | 什么时候填 |
| --- | --- |
| `SIGN_URL` | **必填**。把浏览器地址栏那条签到链接整条粘进引号里。留空会在启动时直接报错退出（不会静默用错任务） |
| `QYWX_KEY` | 想收企业微信推送才填；留空 = 不推送 |

> **不再有 `TASK_ID` / `BASE` 这两个配置项**：站点地址和任务 id 全部从 `SIGN_URL` 里自动解析，避免「链接换了但 taskId 还是旧的」这种错位。换学期只改链接这一处。
>
> `CLIENT_SECRET` 也不用你管：它是学校 App 的 OAuth 客户端常量，是官方前端 JS 里硬编码的公开值（谁打开网页都能看到），**不是你的密码**，代码里已写死。只有学校改版换了这组常量，才需要设 `WQQD_CLIENT_SECRET` 覆盖。
>
> 改完**保存脚本**就生效。这些参数**不需要**再去青龙面板加环境变量；万一临时想覆盖，环境变量仍然优先（见下面第 4 步）。

**各参数含义（详细）**：

| 参数 | 含义 |
| --- | --- |
| `SIGN_URL` | **必填**。整条签到链接，站点地址与 taskId 都由它自动解析；留空则启动即报错退出 |
| `LAT` / `LNG` | 所有账号的默认提交坐标（填宿舍附近即可，服务端只算它和宿舍登记点的距离） |
| `JITTER` | 坐标随机抖动半径（米），`0` = 每次都提交完全相同的坐标 |
| `DRY_RUN` | `true` = 只演练：登录、查任务、打印请求体，**不真正提交**；平时 `false` |
| `FORCE` | `true` = 忽略「今天已签到」跳过逻辑，强制走提交（服务端会回「您今天已完成签到，请勿重复点击！」）；仅测试用，平时 `false` |
| `RETRY` / `RETRY_WAIT` | 失败重试次数 / 每次重试间隔（秒）。**任何错误（接口异常、超时、502/503/504 网关错误等）都会等待 `RETRY_WAIT` 秒后重试，连续 `RETRY` 次（默认 3 次）都失败才判定失败并推送 ❌**。502 只是最常见的错误之一 |
| `EARLY_WAIT` | 定时任务早于签到开始时间触发时，允许原地等待的最大秒数（`0` = 早到一律跳过） |
| `QYWX_KEY` | 群机器人 webhook key 或完整地址，留空则不推送 |
| `NOTIFY` | `false` = 关闭推送（签到照常进行） |
| `NOTIFY_SKIP` | `true` = 连「未到时间 / 非签到日 / 已过时段」这类跳过也推送 |
| `NOTIFY_ALREADY` | `true` = 「今天已签到」也推送。默认关，因为 21:01 成功已推过一条，22:02 兜底只会查到已签到，再推就变一天两条。**签到成功和失败始终会推，不受此开关影响** |

### 3. 只给账号配环境变量

学号、密码属于私密信息，**不要写进脚本文件**（脚本内容会留在青龙服务器上，容易泄露），所以只有账号走环境变量。

青龙面板 →「环境变量」→ 新建。**所有变量统一用 `WQQD_` 开头**（WanQinQianDao = 晚寝签到），在面板里一眼就能看出是哪个脚本的配置：

| 变量名 | 值 | 必填 |
| --- | --- | --- |
| `WQQD_ACCOUNT1` | `888888888` | ✅ |
| `WQQD_PASSWORD1` | `xxxxxxxx`（你的密码**明文**，脚本内部自动 md5） | ✅ |
| `WQQD_ACCOUNT2` | 第二个账号的学号（备用/冗余） | 可选 |
| `WQQD_PASSWORD2` | 第二个账号的密码 | 可选 |
| `WQQD_LAT1` / `WQQD_LNG1` | 第 1 个账号单独用的纬度/经度 | 可选（不填用配置区里的默认坐标） |
| `WQQD_LAT2` / `WQQD_LNG2` | 第 2 个账号单独用的纬度/经度 | 可选 |

> **多账号怎么加**：想加几个账号就顺着编号往下写 `WQQD_ACCOUNT3` / `WQQD_PASSWORD3`、`WQQD_ACCOUNT4` / `WQQD_PASSWORD4` ……最多 20 个。
> 编号**可以不连续**（比如只填 1 和 3），脚本会自动跳过没填的编号。
> 某个编号只填了账号或只填了密码，会在日志里提示「第 N 个账号配置不完整，已跳过」，不会静默漏签。

> **每个账号单独指定坐标**：默认所有账号都用配置区里的 `LAT` / `LNG`。如果某个账号的宿舍不一样，给它单独加 `WQQD_LAT2` / `WQQD_LNG2` 即可；只填其中一个（比如只填 LAT 不填 LNG）会被忽略，退回默认坐标。

> 旧变量名仍然有效（不用改现有配置）：`WISE_ACCOUNT` / `WISE_PASSWORD`（单账号）、`WISE_ACCOUNTS`（多账号写一条 `学号1:密码1&学号2:密码2`，条目后可跟 `@纬度,经度`）。三种来源会合并去重，编号式优先，同一学号只签一次。

### 4. 可选：想临时覆盖配置区才加这些环境变量

配置区里已经有的参数，如果临时想换个值（比如今天想演练一次、想换个 webhook），**加同名环境变量即可覆盖，不用改脚本**：

| 变量名 | 覆盖配置区的哪一行 |
| --- | --- |
| `WQQD_SIGN_URL` | `SIGN_URL`（整条签到链接） |
| `WQQD_LAT` / `WQQD_LNG` | `LAT` / `LNG`（默认坐标） |
| `WQQD_JITTER` | `JITTER`（坐标抖动米数） |
| `WQQD_DRY_RUN` | `DRY_RUN`（`1` = 只演练不提交） |
| `WQQD_FORCE` | `FORCE`（`1` = 忽略「已签到」强制提交） |
| `WQQD_RETRY` / `WQQD_RETRY_WAIT` | `RETRY` / `RETRY_WAIT` |
| `WQQD_EARLY_WAIT` | `EARLY_WAIT`（早到等待秒数） |
| `WQQD_QYWX_KEY` | `QYWX_KEY`（webhook key 或完整地址） |
| `WQQD_NOTIFY` / `WQQD_NOTIFY_SKIP` / `WQQD_NOTIFY_ALREADY` | `NOTIFY` / `NOTIFY_SKIP` / `NOTIFY_ALREADY` |
| `WQQD_NOTIFY_TEST` | （配置区没有此项）`1` = 只打印推送内容不发请求 |
| `WQQD_NOW` | （配置区没有此项）注入 epoch 秒，测试用 |
| `WQQD_CLIENT_SECRET` | （配置区没有此项）学校改版换了 OAuth 常量时才用 |

> `WQQD_QYWX_KEY` 两种填法都支持：只填 key（`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`），或直接填完整地址 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx`。
> `WQQD_SIGN_URL` 填法：把浏览器地址栏那条签到链接整条粘进去，`。

### 5. 设定定时（cron 怎么写）

青龙面板 →「定时任务」→ 新建任务，**命令**填 `task wise_dorm_sign.js`（或直接选脚本），**定时规则**填 cron 表达式。

青龙用的是**5 段式**标准 cron（`分 时 日 月 周`），**不是 6 段，不要写秒**：

```
┌ 分钟 (0-59)
│ ┌ 小时 (0-23)
│ │ ┌ 日   (1-31)
│ │ │ ┌ 月   (1-12)
│ │ │ │ ┌ 星期 (0-7，0 和 7 都表示周日)
│ │ │ │ │
1 21 * * *     ← 每天 21:01:00 执行（推荐）
```

**推荐配置（建两个定时任务）**

| 定时规则 | 作用 |
| --- | --- |
| `1 21 * * *` | 主任务，**21:01** 触发签到（刻意晚 1 分钟，避开整点触发抖动） |
| `2 22 * * *` | 兜底，21:01 失败时 22:02 补签 |

> **为什么写 `1 21` 而不是 `0 21`**：青龙的 cron 在整点触发时会有几秒随机抖动，可能落在 20:59:5x 就执行，而服务端只认 21:00:00 之后，早了会被拒。写 `1 21`（21:01）就彻底避开这个边界。
> 另外脚本本身也有兜底：万一真的早到，只要比 21:00 早不超过 `WQQD_EARLY_WAIT`（默认 120 秒），脚本会原地等到 21:00 再提交，不会白白跳过。
> 21:01 成功的话，22:02 那次会查到「今天已签到」直接跳过，**并且默认不再推送**，所以一天最多一条通知。
> 只有 21:01 失败时你才会收到 ❌，然后 22:02 补签成功再收到一条 ✅ —— 这两条都该收到。

**常用变体**

| cron | 含义 |
| --- | --- |
| `1 21 * * *` | 每天 21:01（**推荐**） |
| `0 21 * * *` | 每天 21:00 整（靠脚本的早到等待兜底） |
| `0,10,20,30,40,50 21-22 * * *` | 21–22 点内每 10 分钟试一次（**最保险**，已签自动跳过） |
| `1 21 * * 1-5` | 只在周一到周五 |
| `1 21 * * 0,6` | 只在周六、周日 |

> 补充：`1 21,2 22 * * *` 这种「分钟位不同却写在一起」的写法是错的——cron 的分钟位只能配同一组，要分两个时间点就建两条定时任务，也就是上面推荐的 `1 21 * * *` + `2 22 * * *`。

⚠️ **时区**：青龙的 cron 按**面板所在时区**解释。国内面板一般是 `Asia/Shanghai`，直接写 `21` 即可；若你的青龙是 UTC，要写 `13`（21−8=13）。确认方式：青龙面板 →「系统设置」→ 时区，或容器环境变量 `TZ=Asia/Shanghai`。

**不用青龙、直接在 Linux 服务器 crontab 跑**（`crontab -e` 加一整行，注意 node 用绝对路径）：

```sh
1 21 * * *  WQQD_ACCOUNT1=888888888 WQQD_PASSWORD1='xxxxxxxx' WQQD_QYWX_KEY=xxxxxxxx /usr/bin/node /root/wise_dorm_sign.js >> /var/log/wise_sign.log 2>&1
```

多账号就继续往后面加变量：

```sh
1 21 * * *  WQQD_ACCOUNT1=888888888 WQQD_PASSWORD1='xxxxxxxx' WQQD_ACCOUNT2=888888889 WQQD_PASSWORD2='xxxxxxxx' WQQD_QYWX_KEY=xxxxxxxx /usr/bin/node /root/wise_dorm_sign.js >> /var/log/wise_sign.log 2>&1
```

**OpenWrt 路由器 crontab**（编辑 `/etc/crontabs/root`；`.sh` 版只支持单账号）：

`.sh` 版的签到链接填在脚本自己的配置区里（`SIGN_URL=` 那一行，整条粘贴；站点地址与 taskId 都从它解析，同样不再单独配 `BASE` / `TASK_ID`）。没填会直接报错退出。

> `.sh` 版同样带重试：登录、拉任务、查记录、提交各步骤只要遇到错误（接口异常、空响应、502/503/504 网关错误等）都会等待 `WQQD_RETRY_WAIT` 秒后重试，连续 `WQQD_RETRY` 次都失败才判失败。两个都走环境变量，默认 `WQQD_RETRY=3`、`WQQD_RETRY_WAIT=20`。

```sh
1 21 * * *  WQQD_ACCOUNT1=888888888 WQQD_PASSWORD1='xxxxxxxx' /bin/sh /root/wise_dorm_sign.sh >> /tmp/wise_sign.log 2>&1
2 22 * * *  WQQD_ACCOUNT1=888888888 WQQD_PASSWORD1='xxxxxxxx' /bin/sh /root/wise_dorm_sign.sh >> /tmp/wise_sign.log 2>&1
```

```sh
/etc/init.d/cron enable && /etc/init.d/cron restart
uci set system.ntp.timezone='CST-8'; uci commit system; /etc/init.d/system restart
```

## 三、参数总表（脚本配置区 ↔ 环境变量）

**优先级：环境变量 > 脚本配置区。** 也就是说配置区里写好的值，只要不设同名环境变量就生效；设了就覆盖。账号只能用环境变量（私密信息不写进脚本）。

### 必填 —— 账号（编号式，`WQQD_` 前缀）

| 变量 | 说明 |
| --- | --- |
| `WQQD_ACCOUNT1` | 第 1 个账号的学号 |
| `WQQD_PASSWORD1` | 第 1 个账号的密码**明文**（脚本内部按官方逻辑 md5 后再提交，不要自己先 md5） |
| `WQQD_ACCOUNT2` / `WQQD_PASSWORD2` | 第 2 个账号（可选，最多到 20；编号可以不连续） |
| `WQQD_LAT1` / `WQQD_LNG1` | 第 1 个账号单独用的坐标（可选，两个都要填才生效） |
| `WQQD_LAT2` / `WQQD_LNG2` | 第 2 个账号单独用的坐标（可选） |

> 兼容旧变量：`WISE_ACCOUNT` / `WISE_PASSWORD`（单账号）、`WISE_ACCOUNTS`（`学号1:密码1&学号2:密码2`，条目后可跟 `@纬度,经度`）。所有来源合并去重，编号式优先，同一学号只签一次。

### 其余参数：配置区优先，环境变量可覆盖

**配置区（`const SETTINGS = { … }`）**

## 四、推送效果

推送用企业微信 markdown 消息。**签到成功、签到失败一定会推**；「今天已签到」默认静音，跳过类默认静音。

**✅ 签到成功**
```
### ✅ 晚寝签到成功
> 日期：2026-11-03 21:01:12（星期二）
> 宿舍：xx-xx-xxx
> 坐标：88.88888, 88.888888（距宿舍 21.4 米）
> 签到时间：21:01:12
> 状态：正常
> 距离宿舍：23.8 米
```

**❌ 失败**（重试完仍失败，一定会推）
```
### ❌ 晚寝签到失败
> 已重试 3 次仍失败
> 原因：<具体错误>
> 时间：2026-11-03 21:01:30
```

**多账号时**：所有账号跑完汇总成**一条**推送，不会一个账号一条。部分失败时标题会写 `❌ 晚寝签到失败（1/2 个账号）`，正文按账号分行列出每个账号的结果：
```
### ❌ 晚寝签到失败（1/2 个账号）
> 共 2 个账号：成功/已签 1 个，失败 1 个
>
> ✅ 账号 888888888（第 1 次）
> 日期：2026-11-03 21:01:12（星期二）
> 宿舍：xx-xx-xxx
> 坐标：88.88888, 88.88888（距宿舍 21.4 米）
> 签到时间：21:01:12
> 状态：正常
> 距离宿舍：23.8 米
>
> ❌ 账号 888888889（第 3 次）
> 原因：登录失败：用户名或密码错误
```

**ℹ️ 今天已签到**（默认**不推**，设 `WQQD_NOTIFY_ALREADY=1` 才推）

这就是你担心的「一天两条通知」：21:01 主任务成功后已经推过 ✅，22:02 兜底那次只会查到「已签到」，默认静音，所以**一天最多一条通知**；如果 21:01 那条失败了，你会收到 ❌，然后 22:02 补签成功会再收到 ✅——这是你想要的，不该省。

```
### ℹ️ 晚寝签到：今天已签到
> 日期：2026-11-03 22:02:03（星期二）
> 宿舍：xx-xx-xxx
> 签到时间：21:01:12
> 状态：正常
> 距离宿舍：23.8 米
```

**⏭ 跳过**（未到时间 / 非签到日 / 任务已结束，默认不推送，除非 `WQQD_NOTIFY_SKIP=1`）

## 五、脚本做了什么

1. 用学号 + `md5(密码)` 调 OAuth 拿 `access_token`。
2. 拉任务详情：签到时段（21:00–23:00）、宿舍 `roomId`、允许半径（400 米）、签到星期、任务起止日期。
3. 依次判断：任务日期范围 → 今天是否签到日 → 是否免签日 → 是否在签到时段。
4. 查当天是否已签到（`signStatus` ∈ {0,1,2,4,5,6} 视为已签，直接跳过）。
5. 生成与前端**逐字段一致**的请求体（含 `stuTaskId`、`signCode` 两个 md5），POST 提交。
6. 提交成功后回查记录确认；失败自动重试（默认 3 次，间隔 30 秒）。
7. 按结果推送企业微信，并设置退出码（成功/已签/跳过 = `0`，失败 = `1`）。

> 多账号时第 1–6 步对每个账号各跑一遍（各自独立重试，一个账号失败不影响其他账号），第 7 步汇总成一条推送。

**退出码**

| 退出码 | 含义 |
| --- | --- |
| `0` | 签到成功 / 今天已签 / 正常跳过（未到时间、非签到日、超出任务日期） |
| `1` | 登录失败、接口异常、签到失败（重试完仍失败）、或缺少签到链接/账号配置 |

> 脚本头部只保留最必要的注释，完整说明（本节及以下内容）都在这个 README 里。

## 六、常见问题

- **返回「签名错误」**：通常是请求缺 `User-Agent`。脚本已固定带上，无需处理。
- **登录 401**：检查 `WQQD_PASSWORD1` 是否是**明文密码**（脚本内部自动 md5，不要自己先 md5）；多账号时检查编号是否对应（`WQQD_ACCOUNT2` 要配 `WQQD_PASSWORD2`），以及是否误把旧写法 `WISE_ACCOUNTS` 里的 `:` 写成别的符号、密码里是否含 `&` 或 `;`（这两个是旧写法的分隔符，含的话请改用编号式变量）。
- **返回「未到签到时间！」**：服务端按**它自己的时间**校验，如果提前手动跑就会这样；等 21:00 后自然正常。
- **企业微信 `errcode 93000`**：webhook 地址/key 不对，去群里重新复制机器人地址。
- **企业微信 `errcode 45009`**：该机器人发消息太频繁，等一会或减少推送（`WQQD_NOTIFY_SKIP=0`）。
- **站点偶发 502 或其它接口错误**：学校网关临时故障等，脚本会等待 `RETRY_WAIT`（默认 30 秒）后自动重试，登录、拉任务、查记录、提交各步骤都适用，连续 3 次（`RETRY`）都失败才判失败并推送 ❌；还有 22:02 那条兜底。
